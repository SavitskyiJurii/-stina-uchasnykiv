# Варіант 2: Render + Postgres — покроково

Версія сайту, яка зберігає дані в базі Postgres, а не у файлі.Тому безкоштовний інстанс Render
можна перезапускати, і він може «засинати» — картки, лайки й коментарі не зникають.

**Файли в цій папці:**
- `server-pg.js` — сервер (той самий API, що й `server.js`, але з базою)
- `package.json` — залежність `pg` і команда старту
- `render.yaml` — опис сервісу й бази для автоматичного деплою
- `index.html` — сам сайт (без змін)

---

## Крок 1. Акаунт Render

Зареєструйтесь на https://render.com через GitHub-акаунт. Картка не потрібна для free-тарифу.

## Крок 2. Залити файли в GitHub

1. Створіть новий **приватний** репозиторій, наприклад `stina-uchasnykiv`.
2. Завантажте в нього 4 файли з цієї папки (кнопка **Add file → Upload files** у веб-інтерфейсі GitHub).
3. Переконайтесь, що `render.yaml`, `package.json`, `server-pg.js` і `index.html` лежать у **корені** репозиторію.

## Крок 3. Створити Blueprint

1. У Render: **New → Blueprint**.
2. Виберіть свій репозиторій. Render прочитає `render.yaml` і покаже, що створить:
   - веб-сервіс `stina-uchasnykiv` (free);
   - базу `stina-db` (free).
3. Натисніть **Apply**. Деплой займе 2–4 хвилини.

## Крок 4. Задати пароль адміністратора

У `render.yaml` пароль позначений як `sync: false` — Render попросить ввести його вручну:

1. Відкрийте сервіс `stina-uchasnykiv` → **Environment**.
2. Знайдіть `ADMIN_PASSWORD` → **Edit** → введіть свій пароль → **Save**.
3. Сервіс перезапуститься сам (1–2 хвилини).

`DATABASE_URL` вписувати не треба — Render підставив його автоматично з бази.

## Крок 5. Перевірити, що все піднялося

Відкрийте адресу сервісу (виду `https://stina-uchasnykiv.onrender.com`).

- Має відкритися стіна з написом **0 / 100**.
- У логах (**Logs**) має бути рядок `Schema ready.` і `Wall (Postgres) running on…`.
- Якщо в логах `DATABASE_URL не задано` — у Environment не прив'язалась база; перевірте, що в `render.yaml` є блок `databases`.

## Крок 6. Тест «переживає перезапуск»

Найважливіша перевірка цього варіанту:

1. Опублікуйте тестову картку з фото.
2. У Render: **Manual Deploy → Restart service** (або дочекайтесь сну інстансу).
3. Оновіть сторінку — картка має залишитися.

Якщо картка зникла, значить сервіс пише не в базу — перевірте, що в Environment `DATABASE_URL` веде на `stina-db`, і подивіться логи.

## Крок 7. Модерація

У підвалі сайту — посилання **«Модерація»**. Пароль той, що ви ввели в кроці 4.
Там: черга на схвалення, видалення карток і коментарів, перемикач попередньої модерації.

Токен входу живе 12 годин і зберігається в пам'яті процесу. Після сну інстансу
доведеться увійти повторно — це нормально.

## Крок 8. Що робити після події

1. **Export даних**: у Render відкрийте `stina-db` → **Connect** → скопіюйте *External Database URL*.
2. Вивантажте дамп (на своєму комп'ютері, потрібен `pg_dump`, ставиться разом з PostgreSQL):
   ```
   pg_dump "ВСТАВТЕ_EXTERNAL_URL" > stina-backup.sql
   ```
3. Фото лежать у самій базі, тому дамп містить усе.

## Крок 9. Обмеження, про які варто знати

| Що | Наслідок |
|---|---|
| Free-інстанс «засинає» після ~15 хв без відвідувачів | перше відкриття після сну — до ~50 секунд |
| Безкоштовна база Render має ліміт розміру й термін життя | перед подією звірте актуальні умови на https://render.com/pricing |
| Фото зберігаються в базі (base64) | ~250–400 КБ на картку; 100 карток ≈ 30–40 МБ — у ліміт вкладається |
| Пароль адміна — змінна середовища | зміна пароля = зміна env + рестарт |

## Локальний запуск (перевірити перед деплоєм)

```
npm install
set DATABASE_URL=postgres://user:pass@host:5432/dbname
set ADMIN_PASSWORD=test123
node server-pg.js
```

Далі http://localhost:8080.

## Перевірено / не перевірено

- **Перевірено:** синтаксис `server-pg.js` (`node --check`), сумісність API з `index.html`
  (маршрути й формати відповідей повторюють `server.js` один-в-один).
- **Не перевірено:** живий прогін проти реальної бази Postgres — у середовищі, де я працюю,
  база не піднялася. Тому першим ділом після деплою зробіть **крок 6**: опублікуйте картку,
  перезапустіть сервіс, перевірте, що вона на місці. Якщо щось впаде — надішліть мені текст
  з Logs, і я виправлю.
